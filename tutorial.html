Tutorial

Make Your First Platformer

In this tutorial you'll make a small platformer, one step at a time: a warrior who runs and jumps between platforms, collects coins, and has a title screen.

Every step has a game you can play, and its code is right under it. Change the code and press Run to see what happens, then press Reset code to put it back. Each step builds on the last one, so the code grows as you go.

In these boxes, MDog Engine is already imported and the screen is set to 256 by 192. In your own game, start with the import line from Getting Started. Any step can also be opened in the Playground to keep working on it.

1. Move a Square

Every game starts with something to control. Here the player is a 14 by 30 box, and its position is a Vector, which holds an x and a y.

MDog Engine runs main() 160 times per second. Each time, it checks the arrow keys with isDown(), moves the player a little, then clears the screen and draws everything again.

Try changing 0.6 to make the player faster or slower.

2. Gravity and Jumping

To jump, the player needs a speed, called its velocity. Every tick, gravity adds a little to the downward speed, and the velocity is added to the position. Jumping sets the speed to point up, and gravity slowly turns it around.

The player can only jump while standing on the ground, so isClicked() is used for the up arrow. It's only true on the tick the key is pressed, so holding it down doesn't keep jumping.

Try changing the gravity (0.06) or the jump speed (-2.7) to make the jump floatier or snappier.

3. Platforms

Checking for the ground by hand works for one floor, but not for lots of platforms. A SquareKickbox is a hitbox that can tell if it's touching another one. The player's kickbox is attached to its position, so it moves along with the player.

The player moves sideways and up or down separately. After each move, if the player's kickbox is touching a platform, the player is pushed back to the platform's edge. Moving one direction at a time makes it easy to tell if the player hit a wall, a floor, or a ceiling.

Try adding another platform to the list, like makePlatform(10, 90, 30, 8).

4. The Warrior

Now the box can become a character. MultipleFileAnimation plays a set of images in order, so the warrior has one animation for standing still and one for running. The animation changes with how the player is moving, and the picture is flipped with flipX when running left.

The warrior's picture is bigger than her hitbox, since it has empty space around her and a sword. So the picture is drawn a little up and to the left of the hitbox, to line her feet up with the bottom of it. The game still uses the simple box for collisions, which is how most platformers work.

To see the hitbox, try adding MDog.Draw.rectangle(playerBox.getLeftX(), playerBox.getTopY(), 14, 30, "#ff0000"); after the warrior is drawn.

5. Coins

Coins give the player something to do. Each coin is a small kickbox, and when the player touches one, it's taken out of the list and the score goes up.

To make collecting a coin feel good, it bursts into sparkles. These are particles from the FX Module. Each one gets a random direction by turning a Vector a random amount with rotate(), and gravity pulls them down.

Try adding more coins to the list, or making the sparkles a different color.

6. A Title Screen and Score

Last, the game gets a title screen, a score in the corner, and a way to play again. Each screen is its own function, and setActiveFunction() switches which one runs. startGame() puts everything back where it started, so the game can be played as many times as you like.

Text is drawn with textImage() and the marsfont.png pixel font. In your own game, the font image goes in your assets folder (see Add Text).

What's Next

That's a whole game! Here are some ideas to try next:

  • Add enemies that walk back and forth on the platforms, and send the player back to the start if they touch one.
  • Make a bigger level with translate(), so the screen follows the player.
  • Add a timer, and try to collect every coin as fast as you can.

The Playground is a good place to keep building, and the Examples and the docs under Code in the sidebar have everything else MDog Engine can do.
